## Default decision rule for new improvements

State the desired benefit, smallest useful implementation, longer-term capability, dependencies, validation and concrete costs/risks. Proceed toward a viable route within the authorized scope. If a substantive constraint blocks that route, explain it and propose an alternative scope, sequence, prototype or validation step. Missing monetization evidence alone is not a sufficient rejection reason.

Every next-work brief should make these distinctions explicit: useful functionality now versus the evidence needed for a stronger intended use; measured constraints versus assumptions; and implementation acceptance versus public-release acceptance. Success criteria may be user usefulness, less founder effort, reliable behavior, accessibility, engagement or reproducible scientific learning. Do not silently replace those criteria with payer counts, generic disclaimer coverage or “avoid medical functionality.”
